# ADR 0018 phase 0: prompt baseline and pre-registered phase 1 gate

- Date: 2026-08-17
- Status: Gate registered (commit 34f3e51, before any capture existed). Scenes frozen (commit 167e74a). All four scenes captured; baseline renders pending. Commit order holds: gate, then freeze, then captures.
- Decision record: docs/decisions/0018-compile-scene-relevant-prompts-and-govern-looks.md
- Harness: fixtures/adr-0018-phase0-capture.mjs
- Scenes: fixtures/adr-0018-phase0-scenes.json

## What phase 0 produces

A pinned baseline: the compiled prompt for each frozen fixture scene, captured verbatim with per section word counts, prohibition density, and failure flags, attributed to a commit. Plus one baseline render per scene, generated by the owner through the deployed app from the captured prompt's job. Every later phase is judged against these captures and renders, never against memory of them.

## Procedure, in order

1. Owner approves or corrects the four scene texts, then the scenes file status flips to `frozen` in its own commit. The harness refuses to run against draft scenes.
2. Owner places the gitignored inputs: each client's approved brain, accepted protection entries, and the MycoPop product record, per the harness header. These are client state and never committed, per ADR 0004.
3. Run the harness on a clean tree at the freeze commit or later. Captures land in fixtures/adr-0018-phase0-captures/ (gitignored). The summary table is appended to this document under Findings, citing the capture commit.
4. Owner generates one render per scene through the deployed app using the same brains and scene briefs, and the render evaluation (three second read per scene) is recorded under Findings.
5. The two protection entries for third party wardrobe and equipment marks are submitted through the refusals flow for both brands, per ADR 0018 phase 0 work item 5.

## The phase 1 gate, registered now

Phase 1 (compile path subtraction and the scene writer rewrite) passes only when all of the following hold on these same frozen scenes:

1. Each compiled prompt lands between 500 and 900 words.
2. Zero impossible invariants: no preservation instruction compiles without a qualifying asset state.
3. Zero inactive direction leakage: no scene's leaked marker list contains an entry.
4. Every statement dropped or transformed by the compiler carries a disposition code recorded in the package.
5. The owner's three second read judges each phase 1 render equal or better than the baseline render for the same scene.

Clause 2 amended 2026-08-18, before any phase 1 work: impossible invariant means a preservation instruction compiled for a job that sends no reference bytes to the renderer, not merely a job with no locked asset record. The MycoPop baseline renders proved the original wording tested the wrong condition. Recorded here rather than corrected silently; the amendment tightens the clause and predates every phase 1 capture.

Clause 6 added 2026-08-18, from the same evidence: no protection instruction compiles a unit count the supplied asset itself violates. A four pack cannot be governed by a rule permitting one readable unit.

Clause 1 recorded as failed and superseded, 2026-08-18, end of day. The gate required every compiled prompt to land between 500 and 900 words. Compiled prompts currently run near 2,200. The clause is not merely unmet, it was wrong: it was written on the assumption that render quality was being suppressed by prompt length, and the day's evidence says the opposite. Every intervention that visibly improved renders added words in a strong early position. The capture block, the look library, the world block, and the human texture floor together account for roughly 900 words and are the only changes all day that moved the image. Meanwhile real subtraction did happen, roughly 250 words of abstract guidance, palette provenance, and duplicate material vocabulary, and none of it was individually visible in a render.

The corrected understanding, recorded for whatever gate replaces this one: what suppressed quality was not length but competing and abstract instruction. Concrete physical facts positioned early beat abstract description positioned anywhere, and word count is a poor proxy for either. A replacement gate should measure whether every compiled statement is a physical fact that can change pixels, and whether any two statements make competing claims about the same property, rather than counting words. This entry is recorded as a fail rather than edited away, per the standing rule that failed gates stay failed.

Gate discipline, per the owner's ruling recorded in ADR 0018: a failed gate halts stacking, not work. Problems found are tweaked within phase 1 against these same scenes until the gate passes. Phase 2 and phase 3 do not start on a failing gate. A mis specified gate clause is a recorded fail, corrected here with a dated amendment, never silently rewritten.

**Finding: the bloat is substantially brand specific.** Dialog Health's baseline is 44 percent leaner than MycoPop's (roughly 1,450 words against 2,610) with prohibition share at 25.8 percent against 44.4. The registered expectation anticipated this possibility and it is now fact: a large share of MycoPop's mass comes from its governed refusal statement, six guardrails, and compiled product record, none of which Dialog Health's baseline carries. Phase 1's subtraction targets are partly universal (structure, dead sections, scene invariant mass) and partly per brand (what governance compiled).

**Finding: the brand mass is scene invariant.** Between the two Dialog Health scenes, every section except Assignment is word identical: roughly 1,290 of 1,450 words do not change when the scene changes. The same holds for MycoPop. This is the dilution mechanism stated plainly: for any given render, close to nine tenths of the prompt is fixed brand payload that competes with the two hundred words describing the actual frame.

**Finding: the cinematic opener is universal in practice.** All four fixture scenes across both brands compile with the cinematic film still opener, because neither brand's creative direction text contains the keyword patterns that select any other mode. The mode library's other three modes are unreachable for both real clients. This hardens the ADR 0018 phase 0 work item 7 finding: mode selection is not just scene blind, it is effectively a constant.

### 2026-08-18: MycoPop baseline renders, and three findings against the compiler

**Renders generated by the owner 2026-08-18, both 4:5 portrait, both reported by the interface as prompt only images.**

Park lifestyle. The audit's failures reproduce. A uniform golden coating sits on the subject, the trees, the path, and every background figure alike. Three background runners occupy the path at similar scale, similarly spaced, all facing away, which is the procession the audit named. The pose is choreographed: the subject holds a quad stretch while holding the can, looking off camera, which is a posed attitude rather than an action. Two audit failures do not reproduce: the bench reads dry, and no third party wardrobe mark is legible. The crop is full body with both shoes in frame, as in the audit's v3.

Four pack product. Better as a photograph and worse as governed output. Scene compliance is high: one can separated from the pack and opened, condensation on the cold surfaces, cutting board with sliced lemon, kettle, single window source from behind and left with the right sides falling into shadow, subject in the left two thirds. The failures are governance failures, below.

**Finding: the impossible invariant is real, and this document's flag for it is mis specified.** The interface reports both renders as prompt only, which the code confirms means the generations endpoint rather than the edits endpoint, so no reference bytes were sent. The compiled prompt nevertheless carries preserve the supplied package exactly as pictured. The instruction therefore cannot be satisfied at render time even though a product record exists at compile time. The earlier finding in this document read the flag as no and reasoned that the record's presence made the invariant possible; that reasoning was wrong, and the flag as implemented tests the wrong thing. It checks whether a locked asset record exists, when the question is whether reference bytes reach the renderer. Corrected in place above rather than rewritten. The phase 1 asset fidelity states must key on delivery, not on record presence, and the gate clause reading zero impossible invariants inherits that definition.

**Finding: the one readable unit rule breaks on a multipack.** The compiled protection reads exactly one package in the frame carries readable branding, and instructs that any further unit be turned away, occluded, cropped, or defocused. The render shows five units with fully legible branding. The rule is not merely disobeyed here, it is incoherent for this SKU: the protected asset is itself a four pack, so the supplied package contains four readable units before the scene adds a fifth. The rule was authored for single unit packages. Phase 1 owes it a unit count concept, and the finding is a concrete instance of the field authority problem phase 2 addresses.

**Finding: package format inference misses the multipack, which suppresses a protection.** `inferPackageFormat` matched no keyword in Mycopop Hibiscus Ginger Lemon 4 Pack, because pack is not in the can pattern, so the format resolved to the generic package. Two consequences compiled. The protection block says package throughout where can would be correct. More consequentially, package is absent from `STATEFUL_FORMATS`, so the closed and sealed sentence never compiled, and no instruction opposed the scene's request for an opened can. The scene and the protection did not actually collide here; the protection was silently absent. A single unit can SKU would have compiled the sealed rule and produced a genuine conflict with the same scene text.

**On the invented label.** Both renders carry coherent, well formed MycoPop lettering including flavor, volume, and ingredient callouts, with no reference bytes sent. Whether any of it matches the real package cannot be judged from here and should not be scored, per the external audit's own guidance that package fidelity stays unscored until a master is supplied. What is recordable is that the failure mode changed: the audit's v2 render produced visibly garbled lettering, while these produce plausible invented lettering, which is the more dangerous outcome because it survives casual review.

### 2026-08-18: format finding, scene amendment, and Dialog Health baseline renders

**Finding: two format tables in app/app.js disagree about the same placement.** The owner caught this when the renders came back 1200x800 at 3:2 while the frozen scenes said 16:9 landscape. Verified in code at head: `placementFormats` (app/app.js line 59) lists Website feature as 16:9 landscape or 4:3 landscape, while `websiteOutputFormats.feature` (line 83) gives 1200 x 800 at 3:2 with its own craft direction. The website studio flow uses the second table and submits the pixel dimensions as the format string. The two tables agree on ratio for every other website placement they share; Website feature is the only genuine contradiction. The scenes file was authored from the first table, so it named a shape the website flow cannot produce.

**Scene amendment, dated 2026-08-18.** Both Dialog Health scenes now carry format 1200x800, matching what the render path submits. The captures were re-run at that format: office interior 1452 words, patient message 1450, prohibition share unchanged at 25.8 and 25.9 percent. The compiled difference is two lines, the assignment and output sentences naming the shape. The word counts in the preceding finding move by two words and no conclusion in it changes.

**A limitation this exposes, recorded rather than resolved.** The captures compile through `compileBrandWorldImagePackage` directly, so they carry whatever brief the harness supplies. The website studio flow additionally passes per format craft direction into the scene writer before generation. These renders were produced with a hand pasted brief rather than a scene writer draft, so the craft direction did not participate, and the captured prompt matches what produced the render. Any future capture whose brief came from the studio scene writer would need the craft field represented. Recorded so a later session does not assume equivalence.

**Baseline renders, Dialog Health, generated by the owner 2026-08-18.**

Clinic front desk. Reads largely taken. The light source is where the scene put it, raking in from the entrance glass; the staff member sits in the right third with the waiting area and glass carrying the left; she is absorbed in the paper rather than performing to the camera. Two failures against the scene as written: the room behind the desk does not fall the step darker the lighting field asked for, and the counter is emptier and tidier than a working front desk an hour before opening. The overall register is competent stock rather than a photograph of a specific clinic.

Kitchen patient message. More staged than the front desk. Window light from camera left is obeyed and the face is lit by the room rather than the screen, which the scene asked for and which is the failure most renders make. The tell is the expression: a contented half smile aimed at the phone, which is the commercial artifice failure the external audit named in the MycoPop test. The kitchen is styled rather than lived in, with the breakfast dishes composed as a still life, and the face carries the campaign clean skin the audit's v3 render also failed to shed.

**Finding: the enemy for Dialog Health is consensus, not error.** Neither render contains a defect of the kind MycoPop's tests produced. There is no invented label, no impossible pose, no third party mark, no golden coating. Both images would pass an untrained review. They fail the three second read by being indistinguishable from competent healthcare stock. This recalibrates what phase 1 has to beat per brand: MycoPop's baseline fails on errors that subtraction and conflict resolution can be expected to fix, while Dialog Health's baseline fails on taste, which is the character layer's job in phase 3. A phase 1 gate that judges Dialog Health renders equal or better may be satisfiable without visible improvement, because there is little error left to remove. Stated in advance of running the gate so the result is not read as more than it is.

**Confound, stated plainly.** Dialog Health's renders are cleaner than MycoPop's audit renders, and its prompt is 44 percent leaner. That is consistent with the dilution thesis and does not demonstrate it. The brands differ in subject matter, scene complexity, and whether a product asset was in play. No causal claim is made from this pair.

**Finding, against this document's own scene fixtures.** The Dialog Health leakage marker lists were authored on the MycoPop pattern (8-bit, arcade, pixel) and probe vocabulary Dialog Health's brain does not contain, so the clean result is weak evidence. Markers probing Dialog Health's own inactive directions belong in the scenes file; that change is a dated scene amendment to make during phase 1 preparation, not a silent edit now.

### 2026-08-19: baseline renders complete, Dialog Health scenes approved, phase 0 closed

**The four baseline renders ran.** All four were generated on 2026-08-19 through the deployed app under their correct clients and received the owner's three second read: mycopop-park-lifestyle and mycopop-fourpack-product under MycoPop, dialog-health-office-interior and dialog-health-patient-message under Dialog Health. This closes the last mechanical item the pre-registration left open.

**Owner read, Dialog Health.** Both frames are the realism baseline. Plain as directed and correct as a starting point. This read doubles as owner approval of both scenes, which converts them from draft to frozen. Their provenance fields in `fixtures/adr-0018-phase0-scenes.json` move from pending to approved with today's date in the same commit as this section, and the file's status note now records that all four scenes carry owner approval. A change from here is a dated amendment.

**Owner read, MycoPop.** Both frames read as carrying residual AI house style. Both causes were traced in the compiled packages rather than assumed, and neither is a compile defect.

The park scene's residual look traces to its own frozen input. The scene's lighting field orders uniform warm dusk with rim lighting, which is the wording the physical register rewrite postdates. The frozen field is doing exactly what it says, and the render is obeying it. The field is retained frozen rather than corrected, because comparability across phases is what the fixture is for and a corrected input would make the phase 1 capture incomparable to this baseline. Recorded here so a later session does not read this as a compile finding.

The four pack's product dimension drift traces to the product record, which lacks a discrete single can cutout. The compile has no isolated single unit to promote, so nothing in the package constrains the proportions of an individual can. This is an open content item for the owner rather than a code item, and it sits alongside the unit count finding already recorded above from 2026-08-17.

**Unplanned finding with evidentiary value: the world block reaches the image.** A client selection error ran both Dialog Health scenes under MycoPop before the correct runs. The error produced something the planned matrix could not: a same scene cross client pair on the clinic desk scene, identical scene text, different declared world.

The Dialog Health run returned the plain clinic. The MycoPop run returned the full declared world: boxy screens, restricted pink and magenta screen light falling on surfaces, laminate, smoked glass, and the can placed as an ordinary object rather than as a hero. This is the first render evidence that the compiled world block reaches the image at all. Until now the world block was verified present in the prompt and unverified in the output.

**The same error also bounds the claim.** The companion error render, the patient kitchen scene under MycoPop, carried the identical world block in its package and showed none of it. World delivery is therefore confirmed and its reliability is scene dependent. That stands as an open observation, not a ruling. The hypothesis, labeled as a hypothesis, is that the world lands when the scene offers furniture compatible with it and does not when the scene's fixtures give the world nothing to attach to. One render exists per condition, which is enough to raise the question and not enough to answer it. No ruling is made and no design change follows from it here.

**Phase 0 is closed as of this section.** Every claim above is Verified from the compiled packages and the renders, except the scene dependence hypothesis, which is labeled as a hypothesis and rests on one render per condition.

**Held, not executed: the aesthetic modes retirement.** Checked before this commit at the owner's instruction. The retirement never shipped. `AESTHETIC_MODES` and its opening lines have been in `src/production/prompt-craft.js` continuously since commit `d87a3b6`, which ported the PWP craft layer into the production compiler, and no later commit removes or replaces them. Verified by compile at head: every package opens with the cinematic film still line regardless of which look is selected, because `resolveAestheticMode` falls back to that mode and the look library sits downstream of it in the Capture section rather than replacing it in Assignment. ADR 0018 ruling five, which replaces the aesthetic modes system with the look library, is therefore unexecuted in code. It is recorded here and held for its own instruction rather than executed inside a documentation commit.
