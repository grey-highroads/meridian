## Product model

Brand World System has two workflows over one persistent Brand Brain:

1. **Build and govern the Brand Brain.** Ingest evidence, distinguish authority, identify contradictions and duplicates, preserve inference as inference, review consequential questions, approve guidance, and separately promote identity-defining material into canon.
2. **Produce from the Brand Brain.** Choose a configured deliverable, provide a brief and optional references, compile relevant knowledge and policy into a portable generation package, render, evaluate, revise, approve, and record the outcome.

Production consumes versioned snapshots. It does not rebuild the brand for each request and cannot silently write to canon.

PWP contributes inference-first world building from incomplete evidence. Riggg contributes controlled production from explicit canon, exact assets, and falsifiable production policy. Preserve both lessons.

## Accepted decisions

- **Separate workflows:** Brand Brain and production are distinct workflows over one source of truth. Production pins a snapshot and cannot silently change canon. See ADR 0001.
- **Approval is not canon:** approval permits scoped use; canonical status is identity-defining and change-controlled. See ADR 0002.
- **Policy is behavior:** constrained, hybrid, and editorial are stage-level configuration presets, not routine user-facing modes. See ADRs 0003 and 0005.
- **Portable preflight:** the generation package contains a read-only prompt, exclusions, inputs, output requirements, policy reference, and provenance. See ADR 0006.
- **Isolated installations first:** reuse a shared versioned core while isolating private client data and configuration. See ADR 0007.
- **OpenAI only initially:** no current product or proof depends on Jim or another renderer. Jim's system may become an optional future adapter.
- **No Responses API for rendering:** prompt-only production uses `/v1/images/generations`; reference-image production uses `/v1/images/edits`. The compiled prompt must remain unchanged. Brand Brain synthesis separately uses Chat Completions. See ADR 0008.
- **Incremental Brand Brain:** new sources create a candidate against the active approved baseline. Unaffected guidance is copied exactly and production changes only after approval. See ADR 0009.

## Current Brand Brain workflow

1. Overview explains the value and permanent navigation.
2. Sources accepts one file, URL, or written record at a time.
3. A concrete material type is chosen before content.
4. Every source requires usage instructions and a guidance area; exclusions are optional.
5. Influence appears only for interpretive sources.
6. Folders and mixed multi-file records are not accepted.
7. Limits are 20 MB per file and 40 MB per synthesis request.
8. Synthesis visibly reads sources, connects the story, checks questions, and prepares a draft.
9. Needs review covers contradictions, possible duplicates, possible principles, and proposed rules.
10. Brand guidance has six rich tabs: foundation, identity, world and story, voice and messaging, creative direction, and creative rules.
11. Artifacts are Brand Dossier, Lived World, and Story Architecture.
12. Inline feedback creates revisions; an exact version can be approved for production.
13. After approval, new sources create a candidate while the active version remains available.

## Source material contract

User-facing types:

1. Protected brand asset: exact logo, package, typeface, lockup, or other file. No influence weight.
2. Approved brand guidance: signed-off brand book, guideline, strategy, or messaging direction. No influence weight.
3. Past brand work or research: campaigns, cases, audits, interviews, or research that show behavior without becoming rules automatically.
4. Single creative image: one visual reference.
5. Image grid or moodboard: one deliberately composed grid file.
6. Named cultural reference: outside context rather than brand truth.
7. Other business document: company context that may inform the brand but is not approved guidance.

Material type sets safe handling but remains a user claim, not automatic authority. Synthesis must compare contents with the declaration and raise a review question on mismatch.

Normalization:

- PNG, JPEG, WebP, and supported images become visual Chat Completions evidence.
- Direct text formats are read locally.
- PDF and Office-style documents use macOS metadata extraction in this local probe.
- Protected unsupported files such as SVG remain metadata and are not visually interpreted.
- Public URL intake blocks private/local networks, limits redirects and size, and strips basic markup.
- Uploaded bytes are used for the active request but stripped from persisted source records.

## Technical implementation

- Plain browser app in `app/`.
- Node server in `scripts/dev-server.js`.
- Node.js 22 or newer.
- Default Brand Brain model: `gpt-5.6`.
- Synthesis: `/v1/chat/completions`, streaming, usage capture, `store: false`, strict JSON Schema.
- Local APIs: `GET /api/brand-brain`, `POST /api/brand-brain/save`, and `POST /api/brand-brain/synthesize`.
- Default store: `.data/brand-brain.json`.
- Image model: `gpt-image-2`.
- Images adapter exists and preserves prompt identity, but browser Generate is still a mock.
- Deterministic protected-asset composition and measurable drift detection are not implemented.

The production compiler is framework-independent, uses eight public schemas, and has SLAKE, PWP, and Riggg fixtures. The Riggg control proves predictable hybrid-versus-constrained behavior with the same brain and assets.
