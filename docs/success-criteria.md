# First Proof: Success Criteria

The first proof is one configured client workflow with a hybrid production stage and one internal constrained control run over a closely related stage request.

## Policy control test

Run the same brand brain, the same approved assets, and closely related stage requests under two policy presets. The policy system succeeds when changing only the stage configuration produces predictable, explainable differences in creative latitude, tools, and evaluation priorities while leaving canon untouched.

The client workflow's hybrid stage should generate a new context while composing locked canonical elements deterministically. The constrained control should reduce invention, narrow acceptable variation, and rank fidelity above novelty. Both runs must retain stage policy snapshots, entity versions, decisions, and evaluations that explain their outputs. The control run is a falsifiability test, not a user-facing mode switch.

## Passing conditions

- A reviewer can identify what was locked, flexible, required, conditional, and prohibited before execution.
- Locked assets are reproduced or placed exactly when direct composition is possible.
- The preset change alters system behavior without duplicating or rewriting the brand brain.
- Drift and unrequested changes are detected and surfaced before final approval.
- Every output can be traced to its request, inputs, entity versions, policy snapshot, tools, and evaluation.
- Corrections may create candidate rules but never silently change canon.
- A useful output can be approved without accidentally becoming canonical.
- Registering an ordinary asset batch is fast enough that required metadata is completed honestly, with exceptions receiving focused review.

## Measures

The pilot should record setup time, production time, correction count, unrequested-change rate, locked-element fidelity, approval rounds, cost, and reviewer confidence in the audit trail. The first target is not a universal benchmark; it is a repeatable baseline that makes later improvements and regressions visible.

## Failure conditions

The proof fails if preset configuration changes only prompt wording, if locked elements are regenerated unnecessarily, if reviewers cannot explain why an output passed, or if production feedback modifies canon without an explicit governed revision event.
